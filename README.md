# SC Player

Компактный модульный SoundCloud-плеер на Go/Fyne для Windows и Linux.
Требования из `instructions.test`: вертикальное окно, поиск, плейлисты,
лента и похожие треки SoundCloud, обложка, очередь, пауза, перемотка,
громкость, светлая/тёмная тема и автоматический запуск интеграции Discord.

## Установка

**Windows x64:** запустите `SC-Player-0.1.0-windows-amd64-setup.exe` из `dist`.
Установщик работает без администратора, создаёт ярлыки и запись удаления,
включает mpv. Обновление сохраняет существующий `sc-player.json`.

**Debian/Ubuntu x64:** после сборки Linux установите пакет:

```sh
sudo apt install ./dist/SC-Player-0.1.0-linux-amd64.deb
```

**Другие Linux:** установите mpv и графические библиотеки средствами
дистрибутива, распакуйте `SC-Player-0.1.0-linux-amd64.tar.gz` и выполните:

```sh
sh install.sh
# По умолчанию ~/.local, при запуске от root — /usr/local.
# Другой каталог: SC_PLAYER_PREFIX=/absolute/path sh install.sh
~/.local/bin/sc-player
```

Удаление переносимой установки: `sh ~/.local/lib/sc-player/uninstall.sh`.
Для нестандартного каталога задайте тот же `SC_PLAYER_PREFIX`.
Пакет удаляется через `sudo apt remove sc-player`. Конфигурация и данные
сессии в системном хранилище сохраняются; кнопка «Выйти» удаляет сессию.
На Linux нужен работающий Secret Service (например, GNOME Keyring) в пользовательской D-Bus-сессии.

## Вход в SoundCloud

Плеер не требует ни ключей, ни регистрации приложения в SoundCloud, и пользователь
ничего не вводит вручную:

- **Без входа** сразу работают поиск, похожие треки и воспроизведение. Публичный
  `client_id` веб-плеера SoundCloud программа сама находит на soundcloud.com при первом
  запуске, кэширует в пользовательском каталоге кэша и обновляет, если SoundCloud его сменил.
- **«Войти»**, если браузер по умолчанию Firefox, открывает soundcloud.com в нём.
  Плеер ждёт, пока сайт выдаст cookie сессии `oauth_token`, и читает её из копии базы
  cookies профиля Firefox (поддерживаются обычная установка, Snap и Flatpak). Если
  пользователь уже вошёл в SoundCloud в Firefox, вход занимает секунду.
- **Другие браузеры** (Chrome, Edge и т. п.) шифруют cookie от сторонних программ,
  поэтому для них «Войти» открывает отдельное окно с сайтом soundcloud.com (системный
  WebView2 на Windows, WebKitGTK на Linux); оно закрывается само после входа.
- В обоих случаях пользователь входит как обычно, любым способом сайта; пароль видит
  только SoundCloud. Токен сохраняется в Windows Credential Manager / Linux Secret
  Service, после чего доступны плейлисты, лайки и лента.
- **«Выйти»** удаляет токен из хранилища плеера, но не выходит из SoundCloud в браузере
  или окне входа: повторный вход в тот же аккаунт пройдёт без пароля. Чтобы сменить
  аккаунт, выйдите на сайте.

Это неофициальный путь: плеер работает через тот же API (`api-v2.soundcloud.com`),
что и сайт. Он может потребовать правки, если SoundCloud изменит сайт.

Окно входа — это тот же исполняемый файл, запущенный с флагом `--soundcloud-login`:
WebView нужен главный поток, а его занимает GUI плеера.

## Трей

Плеер живёт в области уведомлений рядом с часами:

- «Свернуть» и «Закрыть» (×) прячут окно в трей, музыка продолжает играть.
- Левый щелчок по значку возвращает окно; правый открывает меню: текущий трек,
  «Показать плеер», «Пауза»/«Играть», предыдущий и следующий трек, «Выход».
- Повторный запуск (ярлык, меню «Пуск») не открывает вторую копию, а показывает уже
  запущенную.
- Если плеер завершится аварийно или его снимут в диспетчере задач, mpv закроется
  вместе с ним и не будет играть без окна.
- На Linux нужна область уведомлений (StatusNotifierItem: KDE, Cinnamon, XFCE, GNOME с
  расширением AppIndicator). Без неё × закрывает плеер, как раньше.

## Виджет для OBS

1. Нажмите **OBS** в нижней строке плеера и включите **«Включить виджет OBS»**.
   Настройка сохраняется между запусками.
2. Нажмите **«Копировать ссылку»**.
3. В OBS добавьте [источник «Браузер»](https://obsproject.com/kb/browser-source),
   отключите «Локальный файл» и вставьте `http://127.0.0.1:17345/obs` в поле URL.
   Установите ширину **480**, высоту **96**.

Виджет показывает обложку, название и автора на компактной тёмной карточке с
прозрачным фоном вокруг неё. Название и автор занимают по одной строке;
слишком длинные строки обрезаются с многоточием по доступной ширине.
Ширину источника можно уменьшить — карточка подстроится.

При паузе остаётся карточка с отметкой «Пауза». Во время загрузки, после окончания
очереди, выхода из аккаунта или закрытия плеера виджет скрывается.
При следующем воспроизведении он обновляется автоматически. Если OBS открыл
источник до запуска плеера и показывает ошибку загрузки страницы, запустите плеер,
включите виджет и нажмите «Обновить кэш текущей страницы» в свойствах источника.

Плеер и OBS должны работать на одном компьютере: сервер слушает только
`127.0.0.1` и запускается только при включённом виджете. Музыка продолжает играть,
если виджет выключен или его порт занят; ошибка отображается в настройках OBS
в плеере. Звук захватывается средствами OBS отдельно.

## Настройка

Необязательный `sc-player.json` рядом с исполняемым файлом (образец — `sc-player.example.json`).
Путь можно явно задать переменной `SC_PLAYER_CONFIG`; ошибочный файл показывает
понятную ошибку при запуске. Параметры окружения имеют приоритет, включая пустые значения.

| JSON | Переменная окружения | Назначение |
| --- | --- | --- |
| `discord_client_id` | `DISCORD_CLIENT_ID` | Переопределяет вшитый ID приложения Discord (обычно не нужен) |
| `mpv_path` | `MPV_PATH` | Явный путь к mpv, обычно не нужен |

Discord Rich Presence запускается вместе с плеером и не требует настройки от пользователя:
если Discord Desktop запущен, в профиле отображается текущий трек, автор, обложка,
прогресс и кнопка «Открыть в SoundCloud». Discord, запущенный позже, подхватывается
автоматически. В нижней строке окна есть один переключатель — включить/выключить показ,
применяется сразу и запоминается. Музыка работает независимо от Discord.

ID приложения Discord публичный (это не секрет), поэтому он записан прямо в коде:
`DefaultClientID` в `api/discord/presence.go`. Чтобы собрать плеер со своим приложением
из [Discord Developer Portal](https://discord.com/developers/applications), замените его там
или передайте скрипту сборки (`DISCORD_CLIENT_ID=… sh scripts/build-linux.sh`, `-DiscordClientID …`
в PowerShell или строка в `keys.env`).
Пример конфигурации не содержит секретов и игнорируемый `sc-player.json` не попадёт в Git.

## Сборка

Используйте Go версии из `go.mod`. Fyne требует CGO, C-компилятор и системные
графические библиотеки: [официальная инструкция](https://docs.fyne.io/started/quick/).
Тег `ci` предназначен только для тестирования без дисплея; дистрибутивы собираются без него.

### Windows

Установите 64-битный MinGW GCC и [Inno Setup](https://jrsoftware.org/isdl.php).
Для локальной сборки также поддерживается распакованный w64devkit в `.tools/w64devkit`.
Скачайте [Windows-дистрибутив mpv](https://mpv.io/installation/) и распакуйте
его целиком, сохраняя лицензии и документацию.

```powershell
./scripts/build-windows.ps1 -MPVDirectory C:/tools/mpv -Installer
# Конфигурация издателя:
./scripts/build-windows.ps1 -MPVDirectory C:/tools/mpv -ConfigFile ./sc-player.json -Installer
```

Скрипт включает CGO, выбирает amd64, запускает тесты, собирает GUI `.exe`
и установщик в `dist`. Для `.exe` без установщика можно опустить `-Installer`.
`mpv.exe` ищется рядом с приложением, в его `bin/`, затем в PATH.
Установщик создаётся [компилятором ISCC](https://jrsoftware.org/ishelp/topic_compilercmdline.htm).

### Linux

Выполняйте на Linux, а не кросс-компиляцией Go с отключённым CGO:

```sh
sudo apt update
sudo apt install build-essential pkg-config libgl1-mesa-dev libegl1-mesa-dev xorg-dev libxkbcommon-dev libwayland-dev libgtk-3-dev libwebkit2gtk-4.1-dev mpv
sh scripts/build-linux.sh 0.1.0
# Конфигурация издателя: SC_PLAYER_CONFIG=/absolute/path/sc-player.json sh scripts/build-linux.sh 0.1.0
```

Результат: `.tar.gz`, а при наличии `dpkg-deb` — также `.deb` с зависимостями.
GitHub Actions собирает обе ОС и сохраняет установщики в артефактах без публикации релиза.

## Тесты

```sh
go test -tags ci ./...          # без CGO и графического дисплея
go test -tags ci -cover ./...    # покрытие
go vet -tags ci ./...
go test -race -tags ci ./...    # amd64, CGO и C-компилятор
sh scripts/test-linux-installer.sh
# Windows после сборки: ./scripts/test-windows-installer.ps1
# Реальный процесс mpv: SC_PLAYER_MPV_TEST_BINARY=/usr/bin/mpv go test -tags ci ./player
```

Тесты используют поддельный SoundCloud/Discord;
они не требуют аккаунта, не отправляют сообщения в Discord и не воспроизводят звук.
Проверяются поиск client_id и его смена, истечение сессии, разбор токена,
пагинация, догрузка плейлистов, выбор аудиопотока, очередь, IPC mpv,
Discord-фреймы, включение/выключение Rich Presence, конфигурация и виджеты плеера.
Опциональный интеграционный тест запускает настоящий mpv, меняет громкость/паузу,
проверяет перезапуск после аварии и очистку IPC; в CI он включён для обеих ОС.
Для реального входа, аудиовыхода и Discord нужен отдельный ручной прогон.

## Структура

- `app/`: UI и независимые `Module` (поиск, плейлисты, рекомендации).
- `api/soundcloud/`: сессия (client_id, токен в системном хранилище), HTTP API api-v2.
- `internal/weblogin/`: вход на soundcloud.com — через Firefox (чтение cookie профиля) или окно WebView.
- `player/`: очередь и интерфейс `Engine`; mpv управляется по IPC.
- `api/discord/`: `Service` и Rich Presence через локальный IPC Discord.
- `internal/instance/`: одна копия плеера; повторный запуск показывает первую.
- `internal/obs/`: локальная страница «Сейчас играет» для источника «Браузер» в OBS.
- `internal/icon/`, `packaging/icon/sc-player.svg`: иконка. После правки SVG выполните
  `go run ./scripts/icon` (PNG для окна и трея, ICO для установщика); иконку exe
  `build-windows.ps1` создаёт сам (`go run ./scripts/icon -syso`).
- `packaging/`, `scripts/`: установщики, сборка и проверки установки.

Чтобы заменить домашние модули, передайте свои реализации `Module` в `app.New`.
Интерфейсы `Library`, `Engine`, `Service` отделяют UI от сети и аудиодвижка.
Сетевые операции выполняются вне UI-потока; отмена сессии останавливает старые
запросы, очередь не зацикливается, списки используют виртуализированные виджеты.
Обложки ограничены 4 МБ / 4096 px, аудиокэш mpv — 16 МБ.
